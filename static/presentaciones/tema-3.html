01 · Composables e invocación

Declarativo vs. imperativo

Swing (Java)
JPanel panel = new JPanel(); JButton boton = new JButton("Pulsa aquí"); boton.addActionListener(e -> System.out.println("¡Pulsado!")); panel.add(boton);
Compose (Kotlin)
Button(onClick = { println("¡Pulsado!") }) { Text("Pulsa aquí") }

Sin new, sin .add(), sin una variable que se vaya configurando: una función que describe el resultado.

01 · Composables e invocación

Programar el proceso vs. programar el resultado

El mismo cambio de mentalidad que hay entre "escribir un bucle para sumar una lista" y usar .sum().

01 · Composables e invocación

Un composable no es más que una función

  • →Función normal de Kotlin anotada con @Composable: le dice al compilador "esta función describe interfaz".
  • →Button, Text, Column... todos son funciones así, nada más.
  • →Regla especial: un composable solo puede llamarse desde dentro de otro composable.
Saludo.kt
@Composable fun Saludo(nombre: String) { Text(text = "Hola, $nombre") }

Diferencia clave con Java: un método como dibujarSaludo muta vistas ya existentes; Saludo describe qué debe aparecer, y Compose decide cuándo dibujarlo.

01 · Composables e invocación

Anatomía de Button(...) { ... }

Button
Button( onClick = { /* acción */ }, enabled = true, modifier = Modifier.padding(8.dp) ) { Text("Pulsa aquí") }
  • ( )Parámetros con nombre de la función: onClick, enabled, modifier...
  • { }El bloque de llaves es también un parámetro: content, una lambda @Composable () -> Unit.

Si viene de Java, la única novedad real son los parámetros con nombre (onClick = ...), que Java simula con un patrón builder.

01 · Composables e invocación

La trailing lambda: azúcar sintáctico

equivalentes
Button(onClick = { ... }) { Text("Pulsa aquí") } // es exactamente lo mismo que: Button( onClick = { ... }, content = { Text("Pulsa aquí") } )
  • →Regla de Kotlin: si el último parámetro de una función es una lambda, se puede sacar fuera de los paréntesis como bloque { }.
  • →Por eso "acepta contenido": lo de dentro de las llaves son los composables que se dibujan dentro del botón.

Visto con ojos de Java: como pasar dos interfaces funcionales a un método, pero con la facilidad extra de escribir la última como bloque aparte.

01 · Composables e invocación

Componer funciones: el árbol de composición

Pantalla.kt
@Composable fun TarjetaUsuario(nombre: String, email: String) { Column { Text(text = nombre) Text(text = email) } } @Composable fun Pantalla() { Column { TarjetaUsuario("Ana", "ana@x.com") TarjetaUsuario("Luis", "luis@x.com") } }

Una interfaz completa en Compose es un árbol de llamadas a funciones composables. Ese árbol es lo que Compose recorre para dibujar y, más adelante, recomponer.

01 · Composables e invocación

No es lo mismo que anidar Views en XML

  • →El resultado visual puede recordar a anidar <LinearLayout> dentro de otro, pero la mecánica es distinta.
  • →Aquí no se construye un árbol de objetos que luego se infla: se llaman funciones normales de Kotlin.
  • →Eso permite condicionales, bucles, variables locales, funciones auxiliares... mucho más incómodo de expresar en un XML estático.

Cualquier bloque reutilizable de interfaz se extrae como un composable propio, igual que en Java se extrae un método privado para no repetir código.

02 · Componentes de estructura

Organizar la pantalla: layout

  • →No dibujan nada por sí mismos: su trabajo es organizar a sus hijos en el espacio disponible.
  • →Equivalente conceptual a LinearLayout, FrameLayout y RecyclerView del sistema de Views clásico, con una API más directa.
02 · Componentes de estructura

Column: apilar de arriba a abajo

Column
Column( verticalArrangement = Arrangement.SpaceBetween, horizontalAlignment = Alignment.CenterHorizontally ) { Text("Arriba") Text("Abajo") }

verticalArrangement y horizontalAlignment controlan cómo se distribuyen y alinean los hijos.

02 · Componentes de estructura

Row: colocar en horizontal

Row
Row { Icon(Icons.Default.Star, contentDescription = null) Text("Favorito") }

Mnemotécnico: Column apila en columna (vertical); Row coloca en fila (horizontal). El nombre del parámetro de arranque indica el eje que controla.

02 · Componentes de estructura

Box: superponer capas

Box
Box { Image(painter = imagenFondo, contentDescription = null) Text( text = "Título", modifier = Modifier.align( Alignment.BottomStart) ) }

Cada hijo de un Box se posiciona de forma independiente con Modifier.align(...), algo sin sentido en Row o Column.

02 · Componentes de estructura

Combinando los tres

TarjetaProducto
Column { Box { Image(painter = imagenProducto, contentDescription = null) Icon(Icons.Default.Favorite, "Favorito", modifier = Modifier.align( Alignment.TopEnd)) } Row(horizontalArrangement = Arrangement.SpaceBetween) { Text("Zapatillas") Text("49,99 €") } }

La inmensa mayoría de pantallas se construyen anidando estos tres componentes de estructura.

02 · Componentes de estructura

Las variantes Lazy: listas largas

  • →Problema: Column/Row componen todos sus hijos de golpe, aunque solo se vean unos pocos en pantalla.
  • →LazyColumn / LazyRow solo componen lo visible (o casi), y reciclan al hacer scroll — igual que RecyclerView frente a un LinearLayout con scroll.
LazyColumn
LazyColumn { items(listaDeProductos) { producto -> Text(text = producto.nombre) } }

No se escriben los hijos directamente: se usa items(...), con la lista de datos y una lambda que describe cómo dibujar un elemento.

02 · Componentes de estructura

¿Cuándo Lazy y cuándo normal?

ComponenteOrganiza en...Compone todo de golpeEquivalente clásico
ColumnVerticalSíLinearLayout vertical
RowHorizontalSíLinearLayout horizontal
BoxSuperpuesto (capas)SíFrameLayout
LazyColumnVerticalNo (perezoso)RecyclerView vertical
LazyRowHorizontalNo (perezoso)RecyclerView horizontal

Regla práctica: lista fija y corta → versión normal. Colección de datos que puede crecer → versión Lazy, casi siempre.

03 · Componentes comunes

Los controles ya hechos de Material 3

  • →Catálogo amplio: botones, campos de texto, casillas, interruptores... con el aspecto de Material Design listo para usar.
  • →Equivalente a Button, EditText, CheckBox... del sistema de Views clásico, como funciones @Composable.

Muchos de estos componentes no guardan su propio valor: hay que decirles qué mostrar y qué hacer al interactuar. El porqué (estado y recomposición) se verá más adelante — de momento basta con la forma.

03 · Componentes comunes

TextField: entrada de texto

TextField
var texto by remember { mutableStateOf("") } TextField( value = texto, onValueChange = { nuevoValor -> texto = nuevoValor }, label = { Text("Nombre") } )
  • →A diferencia de EditText, no guarda su propio texto: hay que pasarle el valor actual y qué hacer cuando cambia.
  • →remember { mutableStateOf(...) }: la forma de crear un "valor que Compose recuerda entre redibujados" — el mecanismo completo se verá en la siguiente unidad.
  • →OutlinedTextField: mismo comportamiento, estilo de contorno.

03 · Componentes comunes

Image, Icon y los indicadores de carga

Image / Icon
Image( painter = painterResource(id = R.drawable.foto), contentDescription = "Foto de perfil" ) Icon( imageVector = Icons.Default.Favorite, contentDescription = "Favorito", tint = Color.Red )
  • →Image muestra un gráfico. Icon añade tint y exige contentDescription para accesibilidad.
  • →Decorativa: pasa null explícito. Informativa: descripción real. Compose obliga a decidirlo.

CircularProgressIndicator() y LinearProgressIndicator(progress = { 0.6f }): indicadores de carga mientras se espera una respuesta de red.

04 · Material 3: sistema de color

El tema como origen único de los colores

Theme.kt
@Composable fun MiAppTheme( darkTheme: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit ) { val colorScheme = if (darkTheme) DarkColorScheme else LightColorScheme MaterialTheme( colorScheme = colorScheme, typography = Typography, content = content ) }
  • →MaterialTheme es un proveedor de valores: cualquier composable descendiente accede con MaterialTheme.colorScheme.
  • →Por eso un Button ya sale con el color correcto: internamente pide MaterialTheme.colorScheme.primary.
  • →Material Theme Builder: genera el esquema completo (claro/oscuro) a partir de un color de marca.
04 · Material 3: sistema de color

on*: el color que va encima

on-color
Box( modifier = Modifier.background( MaterialTheme.colorScheme.primary) ) { Text( text = "Confirmar", color = MaterialTheme.colorScheme.onPrimary ) }

Cada color de fondo tiene su pareja on<Color>: el que debe usarse para lo que se dibuja encima (texto, iconos) con buen contraste. Nunca hay que tocarlo a mano al cambiar el color de marca.

04 · Material 3: sistema de color

Los roles principales

RolPara qué se usaEjemplo típico
primary / onPrimaryLa acción o elemento más destacadoFondo de un Button principal, FAB
secondary / onSecondaryElementos de apoyo, menos protagonistasChips seleccionados, controles secundarios
tertiary / onTertiaryAcento adicional, de contrasteEtiquetas destacadas, elementos decorativos
error / onErrorEstados de errorTexto o icono de un campo con validación fallida

Tres niveles de énfasis, no un único color "de marca", pensados para jerarquizar visualmente los elementos de una pantalla.

04 · Material 3: sistema de color

Variantes Container y surface

Container
Card( colors = CardDefaults.cardColors( containerColor = MaterialTheme.colorScheme .primaryContainer, contentColor = MaterialTheme.colorScheme .onPrimaryContainer ) ) { Text("Elemento seleccionado") }
  • →primaryContainer...: versión suave y de menor contraste, para superficies grandes donde el color base sería demasiado agresivo.
  • →surface / onSurface: fondo neutro por defecto de pantallas y tarjetas.
  • →surfaceVariant, background, outline: variaciones sutiles y bordes.
04 · Material 3: sistema de color

Cómo elegir el color correcto

PreguntaColor a usar
¿Fondo neutro por defecto de pantalla o tarjeta?surface, background
¿Texto o icono dibujado sobre ese fondo neutro?onSurface
¿Es la acción más importante de la pantalla?primary
¿Texto/icono encima de un color X?onX
¿La misma idea en una superficie grande y suave?XContainer
¿Un estado de error?error / onError

Casi nunca hace falta escribir un color a mano (Color(0xFF...)): se usa el rol del colorScheme que corresponda, y toda la app cambia de aspecto con solo tocar el tema una vez.

05 · Scaffold

El esqueleto completo de pantalla

Scaffold
Scaffold( topBar = { /* barra superior */ }, bottomBar = { /* barra inferior */ }, floatingActionButton = { /* FAB */ }, snackbarHost = { /* avisos */ } ) { paddingValues -> Column(modifier = Modifier.padding(paddingValues)) { Text("Contenido de la pantalla") } }

Scaffold recibe zonas con nombre y, como trailing lambda, el contenido — que recibe paddingValues, el espacio a respetar para no invadir las barras.

05 · Scaffold

Aplicar siempre el paddingValues

  • →Error más común al empezar a usar Scaffold: olvidar Modifier.padding(paddingValues) en el contenido.
  • →Consecuencia: el contenido queda dibujado por debajo de la barra superior o por encima de la inferior, tapado y no accesible.
✗ contenido tapado sin paddingValues

05 · Scaffold

El menú lateral: ModalNavigationDrawer

  • →Cuando hay demasiadas secciones para una barra inferior, o se prefiere otro patrón: un menú que se desliza desde el borde.
  • →No es un parámetro de Scaffold: es un composable que envuelve a todo el Scaffold.
  • →El icono "hamburguesa" en navigationIcon del topBar es, típicamente, el que dispara su apertura.
05 · Scaffold

floatingActionButton y snackbarHost

FAB + Snackbar
val snackbarHostState = remember { SnackbarHostState() } val scope = rememberCoroutineScope() Scaffold( snackbarHost = { SnackbarHost(snackbarHostState) }, floatingActionButton = { FloatingActionButton(onClick = { scope.launch { snackbarHostState.showSnackbar( "Elemento añadido") } }) { Icon(Icons.Default.Add, "Añadir") } } ) { padding -> /* ... */ }
  • →FAB: la acción más importante de la pantalla. Como mucho uno por pantalla.
  • →Snackbar: aviso breve que aparece y desaparece solo. Necesita un SnackbarHostState.
  • →Corrutinas: mostrar un snackbar espera un tiempo, por eso se lanza con scope.launch — se dan por sabidas aquí, se detallan más adelante.
05 · Scaffold

Todas las piezas juntas: jerarquía

El menú lateral envuelve al Scaffold; dentro, cada zona es un parámetro con nombre, y el contenido llega como trailing lambda con el padding a respetar.
